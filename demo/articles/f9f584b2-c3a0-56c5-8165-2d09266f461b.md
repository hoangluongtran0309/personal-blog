## Vì sao lại là microservice?

Khi ứng dụng lớn dần, mỗi lần deploy trở thành một sự kiện đáng sợ. Tách thành các **service nhỏ** giúp từng nhóm triển khai độc lập, scale đúng phần đang chịu tải.

Nhưng microservice không miễn phí: bạn đổi độ phức tạp trong code lấy độ phức tạp trong vận hành.

## Cấu trúc một service

```java
@RestController
@RequestMapping("/orders")
class OrderController {

    private final OrderRepository orders;

    OrderController(OrderRepository orders) {
        this.orders = orders;
    }

    @GetMapping("/{id}")
    Order find(@PathVariable String id) {
        return orders.findById(id).orElseThrow();
    }
}
```

## Docker Compose cho môi trường dev

```yaml
services:
  mongo:
    image: mongo:7
    ports: ["27017:27017"]
  orders:
    build: ./orders
    environment:
      SPRING_DATA_MONGODB_URI: mongodb://mongo:27017/orders
```

## Checklist trước khi tách service

- [x] Ranh giới nghiệp vụ đã rõ ràng
- [x] Có log tập trung và tracing
- [ ] Mỗi service sở hữu dữ liệu của riêng nó

> Đừng tách service chỉ vì "nghe có vẻ hiện đại". Hãy tách khi nỗi đau của monolith là có thật.
